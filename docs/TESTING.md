# Orbit Mobile — Testing & Acceptance

> **Status**: 设计阶段  
> **Purpose**: 给每个里程碑提供"做完算数"的硬性标准

---

## 核心原则

**本地优先的方案，必须用"异常场景"而不是"正常场景"来验收。**

正常场景：用户打字→保存→看到列表——这只能证明 happy path。  
异常场景：断网、杀进程、iCloud 挂了、磁盘满——**这些全通过才算做到本地优先**。

---

## 一、核心验收清单（硬指标）

以下清单覆盖所有里程碑结束后的必过项。没过不合并。

### ✅ 本地优先

- [ ] 飞行模式下完整走一遍保存流程
- [ ] iCloud 账号未登录时保存照常工作
- [ ] iCloud 空间满时优雅提示 + 数据不丢
- [ ] 设备存储只剩 < 100MB 时优雅降级（提示用户清理）
- [ ] 拔网线/关 Wi-Fi/切到"蜂窝关闭"各种组合

### ✅ 原子写入

- [ ] 输入过程中杀进程（`kill -9` 或从 task switcher 划掉）→ 重启后草稿恢复
- [ ] 点"完成"瞬间杀进程（需要人为注入延迟测试）→ 重启后数据完整或完全不存在（**不允许**半成品）
- [ ] 原子写入 Phase 3 各步骤中途崩溃（用 fault injection 测试）→ 启动 reconcile 处理正确
- [ ] 低电量自动关机（用 simulator 强制关机）→ 数据无损
- [ ] 锁屏/切后台/来电中断后继续 → 无数据异常

### ✅ 录音异常

- [ ] 录音过程中来电 → 自动停止 + 已录部分保存为草稿
- [ ] 录音过程中 app 被杀 → 重启后能恢复录音文件
- [ ] 录音过程中切到其他 app 30 分钟后回来 → 录音能正常结束或已妥善保存
- [ ] 录音超过 10 分钟 → 自动分段或正常结束（根据设计决定）
- [ ] 权限被拒时优雅提示，不崩

### ✅ 图片异常

- [ ] 选大图（iPhone 原图 4MB+）→ 压缩正常
- [ ] 选 10 张图一次 → 全部入库
- [ ] 相册权限被拒时优雅提示
- [ ] 拍照过程中切后台 → 无异常
- [ ] 相册选图后切后台再回来 → 选择不丢

### ✅ 同步引擎

- [ ] 100 条积压的 pending → 网络恢复后批量上传，UI 显示进度
- [ ] iCloud 上传中途断网 → failed + 正确退避重试
- [ ] 连续 20 次失败 → 停止重试 + UI 明确提示
- [ ] 手动点"重试"成功后状态正确
- [ ] Mac 端移动 `inbox/<id>/` 到 `processed/` → iOS 端 3 分钟内更新 acked（正常网络）
- [ ] Mac 端写 `.failed.json` retryable=true → iOS 自动重传
- [ ] Mac 端写 `.failed.json` retryable=false → iOS 标 conflicted

### ✅ 崩溃恢复

- [ ] SQLite 损坏（模拟：强行删 orbit.db-wal）→ 启动时从 captures/ 目录重建
- [ ] 手动删除某条 `captures/<id>/` 目录 → 启动扫描标记为 lost，不影响其他
- [ ] 手动删除某条的 `.complete` 标记 → 启动扫描移到 dead-letter
- [ ] 手动破坏 manifest.json 让 sha256 不匹配 → 扫描正常识别

### ✅ 性能

- [ ] 冷启动到键盘就绪 < 1s（P95）
- [ ] 保存点击到 toast < 50ms
- [ ] 列表 100+ 条流畅滚动（60fps）
- [ ] 内存占用 < 80MB

### ✅ 数据不丢

- [ ] 压测：1000 条 capture → 逐一 acked，无丢失
- [ ] 并发压测：Share Extension + 主 app 并发写入 → 无 db 锁死，数据完整
- [ ] 长时间运行（24h）无内存泄漏、无同步卡死

### 手动验收（真机）

### 混沌测试（每次 release 前）

**Fault Injection**：
- 在 `atomic-write.ts` 各阶段埋 `DEBUG_CRASH_AT_PHASE_N` 环境变量
- 启动时根据变量在指定 phase 抛错，模拟各种崩溃时点
- 验证 reconcile 正确恢复

**Chaos Monkey**：
- 后台跑一个脚本随机："每 30-120 秒杀一次 app"
- 运行 1 小时，检查数据库完整性
- 要求：数据不丢、状态机一致

## 五、禁止放过的 bug

以下 bug 级别是 **P0**——发现必须立即修复，不接受"下个版本再说"：

1. **任何数据丢失**
2. **"已保存"但实际数据不存在**
3. **状态机死锁**（某条卡在 syncing 永远不变）
4. **SQLite db lock 导致 app 卡死**
5. **崩溃循环**
6. **iCloud 正常但数据到不了 Mac**

P0 bug 优先级高于任何新功能。

## 六、对新 AI 的建议

如果你接手任务但不确定"做完了没"：

1. 对照本文档找到你所在里程碑
2. 逐项跑验收
3. 跑过的打勾写进 STATUS.md
4. 没跑的或过不了的明确写出来

**"我觉得差不多了" 不是交付标准。**
