## 0. 双模式 Capture

2026-05-16 起，移动端交互拆成两个明确场景：

| 模式 | 用户意图 | 主承载体 | 关键动作 | 不做什么 |
|---|---|---|---|---|
| Markdown Capture | 打开就想记一点东西 | Markdown 草稿 + 附件块 | 写文字、插图片、加文件、录短音频、一次保存 | 不做桌面端完整 Markdown 编辑器 |
| Recording Session | 开会/访谈/现场，需要一直录 | 长录音 + 时间点事件 | 标记此刻，再补笔记/照片/图片/文件 | 不把附件丢成独立 capture |

两者共享同一条底线：用户看到保存成功前，内容和附件必须先完整落到本机 Layer 2。iCloud、AI、Mac ingest 都是后续流程。

### 0.1 Markdown Capture 页面

```
┌──────────────────────────────────────────┐
│ Markdown Capture        录音 最近 设置     │
├──────────────────────────────────────────┤
│ # 标题                                    │
│                                          │
│ 正文、链接、想法……                         │
│                                          │
│ ![photo-1.jpg](attachment://photo-1.jpg) │
│ [deck.pdf](attachment://deck-1.pdf)      │
│ [audio 0:13](attachment://audio.m4a)     │
├──────────────────────────────────────────┤
│ mic  image  file  rec  #/⌄       send     │
└──────────────────────────────────────────┘
```

Markdown 是“capture 的容器”，不是移动端编辑器产品。图片、文件、短录音必须同时表现为：

- 草稿里的 `attachment://` Markdown block
- composer 底部的可移除附件预览
- 保存后的 manifest attachment

### 0.2 Recording Session 页面

```
┌──────────────────────────────────────────┐
│ ×          时间点 转写 来源        完成      │
├──────────────────────────────────────────┤
│ ● 新会议 · 现在                            │
│ 00:12       iPhone 录音                    │
│ waveform                                  │
│ [暂停]              [标记此刻]              │
├──────────────────────────────────────────┤
│ 正在编辑 00:12 · 标记 1                    │
│ 下方操作都会附加到这个时间点                 │
│ [写笔记] [拍照] [图片] [文件]               │
│                                          │
│ 00:12  标记 1    正在编辑                   │
│        这里是关键决策                        │
│        whiteboard.jpg                      │
└──────────────────────────────────────────┘
```

录音模式里“时间点”是第一等对象。用户点“标记此刻”的瞬间就生成精确 timestamp；之后的笔记、照片、文件只是补充这个 timestamp。补充动作必须视觉上属于“正在编辑”的标记面板，不能作为全局并列按钮出现，避免用户误以为它们会创建新的标记。

iPhone 麦克风和 X1 录音卡都进入这一套 Recording Session 页面。X1 的连接、扫描、实时 MP3 接收只是来源状态差异；用户不应该为了 X1 学另一套录音交互。原 `/recording/x1` 页面保留为通信测试台，不作为普通录音入口。

## 1. 启动路径极度扁平

### 1.1 冷启动规范

```
点图标
   ↓ 150ms (launch screen)
主界面渲染完成 + 键盘弹起 + 光标就位
   ↓ 用户开始输入
```

**目标**：图标点击到键盘就绪 **< 1 秒 P95**。

### 1.2 实现要点

- **没有启动动画**（Launch Screen 用纯色 + logo）
- **没有 onboarding 拦截**（首次用户除外，最多 2 屏）
- **没有首页 / 列表页**——图标点开就是输入界面
- **没有登录**——本地优先不需要账号
- **预热策略**：
  - SQLite 在 app 启动后异步打开（不阻塞首屏渲染）
  - ReconcileJob 在后台线程跑
  - iCloud 状态查询异步
  - AVAudioSession 预初始化（减少按录音按钮时的启动延迟）
  - 粘贴板预读（有 URL 时悄悄准备"粘贴并保存？"条）

## 2. 主界面布局

```
┌──────────────────────────────────────────┐
│  ✓ 已同步                     [最近]      │ ← 顶部状态条（小）
├──────────────────────────────────────────┤
│                                          │
│  [ 想法、灵感、见闻、问题……         ]     │
│                                          │
│                                          │ ← TextInput，autoFocus
│                                          │   多行，无边框
│                                          │   iOS 系统级 "书写中" 光标
│                                          │
│                                          │
│                                          │
│                                          │
├──────────────────────────────────────────┤
│  mic  image  rec  #/⌄          send       │ ← 图标工具条
└──────────────────────────────────────────┘
```

### 2.1 顶部状态条（不抢视觉）

- 高度 32pt，小字
- 左：全局同步状态（✓ / ↑ N 条待同步 / ⚠ iCloud 未登录 / ✈ 离线）
- 右：「最近」按钮，进列表页
- 不显示 tab 栏——只有输入一个 tab

### 2.2 中间输入区

- 占 85% 屏幕高度
- **autoFocus = true**
- Placeholder 文案随机换（让每次打开有"呼吸感"）：
  - "今天想记什么？"
  - "最近在想什么？"
  - "捕捉这一刻……"
  - "写下一个想法……"
- 支持多行，换行不触发保存
- 打字时**不显示**任何按钮干扰（底部操作条常驻但低对比度）

### 2.3 底部操作条

- 高度 48pt
- 全部使用图标，不使用"按住说话 / 图片 / 完成"这类文字按钮
- mic：按住转文字，同时保留原始录音，松开后作为语音附件 chip 留在 composer
- image：相册多选 / 拍照入口，选完只加入预览，不立刻保存
- rec：进入长录音 Capture
- #：快捷插入标签；键盘打开时切换为收起键盘图标
- send：右下主操作，保存当前文字 + 图片 + 语音为同一条 Capture

**Haptics**：
- 按保存 → light impact
- 录音开始 → soft impact
- 保存成功 → success notification

## 3. 语音输入交互

### 3.1 按住说话（推荐）

```
用户长按 🎙
   ↓
按下瞬间：震动 (soft impact) + 录音指示器动画 + 开始录音
   ↓
同时：实时转写的文字流入 TextInput
   ↓
用户一边说一边看文字出现
   ↓
松开：停止录音 + 最终文字固定 + 原始录音作为附件 chip 留在 composer
   ↓
用户可继续补文字 / 加图片 / 点 send 一次保存
```

**交互细节**：
- 按下即开始，不要"先确认再开始"的对话框
- 手指滑出按钮范围**不取消录音**（避免误操作），只在松手时判断
- 录音指示器：底部浮现一条声波动画 + 时长
- 松开后输入框的文字可以继续编辑；未点 send 前不跳页、不清空

### 3.2 切换到"锁定录音"模式

长按 🎙 > 0.5s 后向上滑 → 锁定录音，手指可以离开
- 适合长时间记录
- 屏幕上浮现"点击结束"按钮

### 3.3 仅录音不转写

`🎙` 长按里右滑 → 切到"只录音"模式
- 用于安静环境不方便说话、噪音环境转写不准、隐私场景
- 产物：纯 `.m4a` 附件，无转写文本
- Mac 端可选用 Whisper 二次处理

### 3.4 转写失败兜底

- iOS 原生转写失败 → **保留录音** + 输入框显示 `[语音录制 34s]` 占位
- 用户可继续打字补充
- Mac 端收到后尝试 Whisper 转写

## 4. 图片输入

### 4.1 交互

```
点 📷
   ↓
底部 Sheet 弹出：[ 拍照 | 从相册选 | 取消 ]
   ↓
拍照 → 系统相机
或
相册 → 系统图片选择器（多选）
   ↓
选完后：composer 内出现缩略图（可滑动）
   ↓
每张可点 × 移除
   ↓
用户可继续输入文字 / 继续加图 / 加语音
```

图片、文字、语音属于同一个 composer。保存时如果同时有文字和图片，产物是 `mixed` capture；只有图片时是 `photo` capture；所有附件继续走本地原子写入协议。

### 4.2 压缩策略

| 场景 | 默认 |
|---|---|
| 选图/拍照 | 长边 2048px，质量 0.8，自动压缩 |
| 用户长按缩略图 → "保留原图" | 用原图 |
| 用户设置"总是保留原图" | 用原图 |
| Wi-Fi / 蜂窝区别 | 可选 "仅 Wi-Fi 保留原图" |

压缩**异步**——不阻塞"保存"点击。原图在 tmp，压缩完成替换后再原子写入。

## 5. 保存 + 连续捕获

### 5.1 保存流程

```
点"完成"
   ↓
UI 立即给出反馈：
  - 输入框淡出
  - 底部出现 "已保存 ✓" toast
  - haptic success
   ↓
后台走原子写入协议（< 200ms）
   ↓
输入框清空，再次 autoFocus
   ↓
用户可以直接继续下一条
```

主输入页实际按钮是 send 图标，不显示"完成"文字；语义仍是一次性保存当前 composer 内所有内容。

**关键**：**不要**跳走、不要弹结果页、不要问"要不要分享到..."。保存后立刻回到输入状态。

### 5.2 "完成并退出"

需要有一个明确的退出手势：
- 左上 `×` 按钮：保存当前内容并关闭键盘
- 下滑屏幕：关闭键盘但不退出
- 双击 "完成"：保存 + 关闭键盘

### 5.3 空内容不保存

- 输入框空 + 无附件时，"完成" 按钮 disable
- 防止误按

## 6. 同步状态的透明度

### 6.1 每条 capture 的视觉状态

列表页（「最近」按钮进入）：

```
┌─────────────────────────────────────────┐
│ 今天在地铁上想到…         刚刚    ○      │  pending（白点）
│ 一个关于 capture 的想法…             ●  │  syncing（蓝点）
│ 上周日的灵感                         ●  │  uploaded（蓝点）
│ 周五的思考                           ✓  │  acked（绿点）
│ 早上的一条…                          ⚠  │  failed（橙色警告）
│ 昨天的…                              ⛔  │  conflicted（红色）
└─────────────────────────────────────────┘
```

### 6.2 详情页

每条 capture 的详情页：
- 完整内容 + 所有附件
- 状态 badge（大）
- 最近 5 条 sync_events 时间轴
- 按钮：「立即重试」「查看本地文件」「导出」

### 6.3 全局状态栏

顶部 32pt：
- 绿：`✓ 已同步`（所有条目都 acked）
- 蓝：`↑ 5 条正在同步`
- 灰：`✈ 离线模式（5 条已本地保存）`
- 橙：`⚠ iCloud 未登录，5 条等待同步`
- 红：`⛔ 同步错误` 点击进详情

**用户对数据的信任 = 状态的透明度**。不要隐藏失败。

### 7.1 屏 1 — 价值主张

```
┌────────────────────┐
│                    │
│    💡 Orbit         │
│                    │
│  随时记，          │
│  永不丢。           │
│                    │
│                    │
│  [ 下一步 ]         │
└────────────────────┘
```

### 7.2 屏 2 — iCloud 前置

```
┌────────────────────┐
│                    │
│  启用 iCloud 同步   │
│                    │
│  你的想法会同步到     │
│  Mac 端 Orbit，     │
│  永远是你自己的数据。 │
│                    │
│  [ 启用 ]           │
│  [ 稍后 ]           │
└────────────────────┘
```

- "启用" → 检查 iCloud 状态 → 如果不可用，展示具体引导
- "稍后" → 进主界面，顶部状态栏显示警告

**就这么多**。任何多出来的屏都是阻碍。

## 8. 异常状态的友好提示

| 状态 | UI |
|---|---|
| iCloud 未登录 | 顶部橙色 banner："请在 iOS 设置 > iCloud 登录账号" + 按钮跳转系统设置 |
| iCloud 空间满 | 顶部橙色 banner："iCloud 空间已满，数据已在本地" + 按钮 "查看管理方案" |
| 网络断开 | 顶部灰色 "✈ 离线模式" — **不打扰**，这是正常状态 |
| 某条 sync 失败 20+ | 详情页红色卡片 + "需要手动介入" + "联系支持"链接 |

## 9. 辅助功能

- **VoiceOver** 支持全量
- **Dynamic Type** 响应系统字号
- **Dark Mode** 默认跟随系统
- **Reduce Motion** 时禁用录音动画等

## 10. 性能指标（UX 相关）

| 指标 | 目标 |
|---|---|
| 冷启动到键盘就绪 | < 1s P95 |
| 点"完成"到 toast 出现 | < 50ms |
| 录音按下到开始录音 | < 100ms |
| 图片选完到预览显示 | < 300ms |
| 列表滑动 FPS | 60fps |
| 输入字符延迟 | 无感知（< 16ms） |

## 11. 不做的交互（克制清单）

- ❌ 启动动画
- ❌ 多屏 onboarding（超过 2 屏）
- ❌ Tab 栏（只有 Capture 一件事）
- ❌ 首页
- ❌ 账号登录
- ❌ 项目/标签必选
- ❌ 保存确认对话框
- ❌ 分享弹窗（保存后就结束）
- ❌ 广告
- ❌ 推送通知（这是 Capture 工具，不是沟通工具）
- ❌ 成就/打卡/游戏化
- ❌ 评分弹窗
- ❌ "新功能介绍" 弹窗
