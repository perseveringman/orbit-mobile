# Orbit Mobile — UX Principles

> **Status**: 设计阶段  
> **Target readers**: 设计师、写 UI 代码的 AI

## 核心信条

```
┌──────────────────────────────────────────────────────┐
│  移动端 Capture 的敌人是"多按一次都嫌多"                  │
│  我们的目标：从"想到要记"到"记下来"< 3 秒                  │
└──────────────────────────────────────────────────────┘
```

---

## 1. 启动路径极度扁平

### 1.1 冷启动规范

```
点图标
   ↓ 150ms (launch screen)
主界面渲染完成 + 键盘弹起 + 光标就位
   ↓ 用户开始输入
```

**目标**：图标点击到键盘就绪 **< 1 秒 P95**。

### 1.2 实现要点

- **没有启动动画**（Launch Screen 用纯色 + logo）
- **没有 onboarding 拦截**（首次用户除外，最多 2 屏）
- **没有首页 / 列表页**——图标点开就是输入界面
- **没有登录**——本地优先不需要账号
- **预热策略**：
  - SQLite 在 app 启动后异步打开（不阻塞首屏渲染）
  - ReconcileJob 在后台线程跑
  - iCloud 状态查询异步
  - AVAudioSession 预初始化（减少按录音按钮时的启动延迟）
  - 粘贴板预读（有 URL 时悄悄准备"粘贴并保存？"条）

## 2. 主界面布局

```
┌──────────────────────────────────────────┐
│  ✓ 已同步                     [最近]      │ ← 顶部状态条（小）
├──────────────────────────────────────────┤
│                                          │
│  [ 想法、灵感、见闻、问题……         ]     │
│                                          │
│                                          │ ← TextInput，autoFocus
│                                          │   多行，无边框
│                                          │   iOS 系统级 "书写中" 光标
│                                          │
│                                          │
│                                          │
│                                          │
├──────────────────────────────────────────┤
│  🎙   📷   #            [ 完成 ]          │ ← 底部操作条
└──────────────────────────────────────────┘
```

### 2.1 顶部状态条（不抢视觉）

- 高度 32pt，小字
- 左：全局同步状态（✓ / ↑ N 条待同步 / ⚠ iCloud 未登录 / ✈ 离线）
- 右：「最近」按钮，进列表页
- 不显示 tab 栏——只有输入一个 tab

### 2.2 中间输入区

- 占 85% 屏幕高度
- **autoFocus = true**
- Placeholder 文案随机换（让每次打开有"呼吸感"）：
  - "今天想记什么？"
  - "最近在想什么？"
  - "捕捉这一刻……"
  - "写下一个想法……"
- 支持多行，换行不触发保存
- 打字时**不显示**任何按钮干扰（底部操作条常驻但低对比度）

### 2.3 底部操作条

- 高度 48pt
- 🎙 **按住说话**（核心交互，加大加粗）
- 📷 图片入口
- # 标签快捷输入
- "完成" 按钮：右下，主色

**Haptics**：
- 按保存 → light impact
- 录音开始 → soft impact
- 保存成功 → success notification

## 3. 语音输入交互

### 3.1 按住说话（推荐）

```
用户长按 🎙
   ↓
按下瞬间：震动 (soft impact) + 录音指示器动画 + 开始录音
   ↓
同时：实时转写的文字流入 TextInput
   ↓
用户一边说一边看文字出现
   ↓
松开：停止录音 + 最终文字固定
```

**交互细节**：
- 按下即开始，不要"先确认再开始"的对话框
- 手指滑出按钮范围**不取消录音**（避免误操作），只在松手时判断
- 录音指示器：底部浮现一条声波动画 + 时长
- 松开后输入框的文字可以继续编辑

### 3.2 切换到"锁定录音"模式

长按 🎙 > 0.5s 后向上滑 → 锁定录音，手指可以离开
- 适合长时间记录
- 屏幕上浮现"点击结束"按钮

### 3.3 仅录音不转写

`🎙` 长按里右滑 → 切到"只录音"模式
- 用于安静环境不方便说话、噪音环境转写不准、隐私场景
- 产物：纯 `.m4a` 附件，无转写文本
- Mac 端可选用 Whisper 二次处理

### 3.4 转写失败兜底

- iOS 原生转写失败 → **保留录音** + 输入框显示 `[语音录制 34s]` 占位
- 用户可继续打字补充
- Mac 端收到后尝试 Whisper 转写

## 4. 图片输入

### 4.1 交互

```
点 📷
   ↓
底部 Sheet 弹出：[ 拍照 | 从相册选 | 取消 ]
   ↓
拍照 → 系统相机
或
相册 → 系统图片选择器（多选）
   ↓
选完后：输入框上方出现缩略图（可滑动）
   ↓
每张可点 × 移除
```

### 4.2 压缩策略

| 场景 | 默认 |
|---|---|
| 选图/拍照 | 长边 2048px，质量 0.8，自动压缩 |
| 用户长按缩略图 → "保留原图" | 用原图 |
| 用户设置"总是保留原图" | 用原图 |
| Wi-Fi / 蜂窝区别 | 可选 "仅 Wi-Fi 保留原图" |

压缩**异步**——不阻塞"保存"点击。原图在 tmp，压缩完成替换后再原子写入。

## 5. 保存 + 连续捕获

### 5.1 保存流程

```
点"完成"
   ↓
UI 立即给出反馈：
  - 输入框淡出
  - 底部出现 "已保存 ✓" toast
  - haptic success
   ↓
后台走原子写入协议（< 200ms）
   ↓
输入框清空，再次 autoFocus
   ↓
用户可以直接继续下一条
```

**关键**：**不要**跳走、不要弹结果页、不要问"要不要分享到..."。保存后立刻回到输入状态。

### 5.2 "完成并退出"

需要有一个明确的退出手势：
- 左上 `×` 按钮：保存当前内容并关闭键盘
- 下滑屏幕：关闭键盘但不退出
- 双击 "完成"：保存 + 关闭键盘

### 5.3 空内容不保存

- 输入框空 + 无附件时，"完成" 按钮 disable
- 防止误按

## 6. 同步状态的透明度

### 6.1 每条 capture 的视觉状态

列表页（「最近」按钮进入）：

```
┌─────────────────────────────────────────┐
│ 今天在地铁上想到…         刚刚    ○      │  pending（白点）
│ 一个关于 capture 的想法…             ●  │  syncing（蓝点）
│ 上周日的灵感                         ●  │  uploaded（蓝点）
│ 周五的思考                           ✓  │  acked（绿点）
│ 早上的一条…                          ⚠  │  failed（橙色警告）
│ 昨天的…                              ⛔  │  conflicted（红色）
└─────────────────────────────────────────┘
```

### 6.2 详情页

每条 capture 的详情页：
- 完整内容 + 所有附件
- 状态 badge（大）
- 最近 5 条 sync_events 时间轴
- 按钮：「立即重试」「查看本地文件」「导出」

### 6.3 全局状态栏

顶部 32pt：
- 绿：`✓ 已同步`（所有条目都 acked）
- 蓝：`↑ 5 条正在同步`
- 灰：`✈ 离线模式（5 条已本地保存）`
- 橙：`⚠ iCloud 未登录，5 条等待同步`
- 红：`⛔ 同步错误` 点击进详情

**用户对数据的信任 = 状态的透明度**。不要隐藏失败。

## 7. 首次启动引导（最多 2 屏）

### 7.1 屏 1 — 价值主张

```
┌────────────────────┐
│                    │
│    💡 Orbit         │
│                    │
│  随时记，          │
│  永不丢。           │
│                    │
│                    │
│  [ 下一步 ]         │
└────────────────────┘
```

### 7.2 屏 2 — iCloud 前置

```
┌────────────────────┐
│                    │
│  启用 iCloud 同步   │
│                    │
│  你的想法会同步到     │
│  Mac 端 Orbit，     │
│  永远是你自己的数据。 │
│                    │
│  [ 启用 ]           │
│  [ 稍后 ]           │
└────────────────────┘
```

- "启用" → 检查 iCloud 状态 → 如果不可用，展示具体引导
- "稍后" → 进主界面，顶部状态栏显示警告

**就这么多**。任何多出来的屏都是阻碍。

## 8. 异常状态的友好提示

| 状态 | UI |
|---|---|
| iCloud 未登录 | 顶部橙色 banner："请在 iOS 设置 > iCloud 登录账号" + 按钮跳转系统设置 |
| iCloud 空间满 | 顶部橙色 banner："iCloud 空间已满，数据已在本地" + 按钮 "查看管理方案" |
| 网络断开 | 顶部灰色 "✈ 离线模式" — **不打扰**，这是正常状态 |
| 某条 sync 失败 20+ | 详情页红色卡片 + "需要手动介入" + "联系支持"链接 |

## 9. 辅助功能

- **VoiceOver** 支持全量
- **Dynamic Type** 响应系统字号
- **Dark Mode** 默认跟随系统
- **Reduce Motion** 时禁用录音动画等

## 10. 性能指标（UX 相关）

| 指标 | 目标 |
|---|---|
| 冷启动到键盘就绪 | < 1s P95 |
| 点"完成"到 toast 出现 | < 50ms |
| 录音按下到开始录音 | < 100ms |
| 图片选完到预览显示 | < 300ms |
| 列表滑动 FPS | 60fps |
| 输入字符延迟 | 无感知（< 16ms） |

## 11. 不做的交互（克制清单）

- ❌ 启动动画
- ❌ 多屏 onboarding（超过 2 屏）
- ❌ Tab 栏（只有 Capture 一件事）
- ❌ 首页
- ❌ 账号登录
- ❌ 项目/标签必选
- ❌ 保存确认对话框
- ❌ 分享弹窗（保存后就结束）
- ❌ 广告
- ❌ 推送通知（这是 Capture 工具，不是沟通工具）
- ❌ 成就/打卡/游戏化
- ❌ 评分弹窗
- ❌ "新功能介绍" 弹窗
