# ADR-004: User-key DeepSeek V4 Flash for recording AI notes

**Status**: accepted  
**Date**: 2026-05-15

## Context

M9 shipped real local recording notes, but summaries, decisions, risks, todos, custom templates, and Ask Orbit were generated by local heuristics. The app must keep Orbit Mobile's local-first and no-server constraints while making AI output genuinely model-generated.

## Decision

Orbit Mobile will call DeepSeek's OpenAI-compatible Chat Completions API directly from the device using a user-provided API key. The default provider config is `base_url=https://api.deepseek.com` and `model=deepseek-v4-flash`.

The API key is stored only in iOS Keychain through `expo-secure-store`; SQLite stores only non-sensitive settings. AI jobs run after recording capture has already been written locally. Only transcript text, timestamps, and existing note context are sent to DeepSeek. Raw audio and image originals are not uploaded to the AI provider.

## Consequences

- The app gains real AI notes and Ask Orbit without adding a server, account system, or proprietary cloud.
- Capture success remains independent from AI availability; missing keys, offline errors, or provider failures produce visible retry/skipped states.
- SyncWorker waits for queued/running AI note tasks before the first upload of a recording capture, so Mac usually receives AI-generated derivative files instead of local heuristic placeholders.
- DeepSeek V4 Flash is text-only in this integration; it does not replace Apple Speech or provide final `.m4a` transcription/diarization.
